# QA record: TOKI-093
Ticket: TOKI-093
Spec: docs/specs/2026-11-16-destructive-patterns-design.md
Version: 420d129
Environment: a temporary worktree of the Version under Node 22 (`~/.nvm`), pnpm through corepack, macOS; Vitest 5.1.0 with jsdom for the rendering rows; `tsc` of the repository for the type rows; the Vite dev server of `apps/web` on a free loopback port and the headless Chromium cached by Playwright 1.65.1 for the browser rows; no PostgreSQL (the row that needs one is Blocked); the repository itself is not changed

Role: Dev is Thanh Truong with Claude (the ticket was built before this record). QA is Thanh Truong. Claude drafts the rows; the QA approves them before any row is run. Claude runs the command rows; the QA runs the manual row.

Each command row runs `V=420d129 bash docs/qa/TOKI-093.checks.sh <ID>` (called `checks` below) and compares its one output line with Expected. The output goes in `docs/qa/TOKI-093.evidence.txt`. `420d129` is the merge commit of PR #151, decided in concern 1 of the spec of this record. Rows that run code use a temporary worktree of the Version with throwaway test, type and page files that exist only there; rows that read text are paired with the same scan of a copy changed in memory, and rows that change a file of the worktree restore it. A row names one requirement and one behavior; where a requirement has several behaviors it has several rows, and each part of a sentence is a printed number. Rows T7, T12 and T15 keep what the spec of TOKI-093 says; the code at the Version is known to differ in T7 (the configuration sets `environment: "node"` and each test opts into jsdom with a docblock) and T15 (`lint:boundaries` is not a script), and T12 needs a PostgreSQL test database that the checks do not start. No `.env` is read or created; no secret and no tool output is kept.
