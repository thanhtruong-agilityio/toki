# Intent: Create the mobile app skeleton

Author: Huy Nguyen

## Problem

Toki's phone app (roadmap phase 3) is planned in the Blueprint's Mobile App Plan, but the repository has no place for it. `apps/mobile` does not exist, and nothing shows that the shared packages (`shared`, `client-core`, `tokens`, `i18n`, `platform`) load in a React Native app. They were built for that reuse, but only the web app has used them so far. Every other MM1 ticket (CI, tests, tokens, components, the app shell) needs an app to build in, and needs to know that the workspace packages resolve in it.

## Proposed outcome

- `apps/mobile` exists in the pnpm workspace as an Expo app with Expo Router and TypeScript.
- One screen runs on an iOS simulator and an Android emulator, in a development build.
- The app imports a workspace package from source, with no build step, as the web app does.
- `pnpm install`, `pnpm typecheck`, `pnpm lint` and `pnpm test` still pass at the root, and the web app is unchanged.

## Affected users and systems

- Users: the engineers who build the app. No member sees this ticket's work. Source: Toki Blueprint, Mobile App Plan, intent IM01.
- Systems: the pnpm workspace (root `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `.gitignore`), the new `apps/mobile`, and the workspace packages it imports. Source: Toki Blueprint, Mobile App Plan, MOB-03.

## Constraints

- Blueprint ticket MOB-03 "The `apps/mobile` skeleton", from web tickets TOKI-001 and TOKI-006. Size M. Source: Toki Blueprint, Mobile App Plan, MM1, area Repository foundation.
- Milestone: MM1 "Mobile foundation and design system". Outcome: IM01, "A mobile app in the repository, with the same rules, tooling and CI as the web". Source: Toki Blueprint, Mobile App Plan.
- Needs: no other mobile ticket. Source: Toki Blueprint, Mobile App Plan, notes on the order of work.
- Needed by: every other MM1 ticket that adds code to `apps/mobile` or `packages/ui-native`. Source: Toki Blueprint, Mobile App Plan, MM1.
- React Native with Expo, for iOS and Android. Source: decision D-024; Toki Blueprint, Roadmap, phase 3.
- Expo Router and TypeScript, in the pnpm workspace; Metro resolves the workspace packages. Source: Toki Blueprint, Mobile App Plan, MOB-03.
- The repository layout names `apps/mobile` as "React Native + Expo (phase 3)". Source: Toki Blueprint, Technical, code structure.
- Workspace packages are named `@toki/<folder>`, are ES modules, and are consumed from source with no build step. Source: TOKI-001 spec, concerns 1 and 2.
- Tool versions are the stable release in use when the ticket is built, pinned exactly. Source: TOKI-001 spec, concern 3.
- Node 22 and the pnpm version of the root `package.json`. Source: TOKI-001 spec, R8 and R9.
- The app runs as a development build, not in Expo Go. Source: Toki Blueprint, Mobile App Plan, MM1 exit check ("the dev build runs on an iOS simulator and an Android emulator").
- One app in the stores serves every company. Source: Toki Blueprint, Mobile App Plan, decision Q1.
- iOS and Android builds run on our own GitHub Actions, not on a hosted build service. Source: Toki Blueprint, Mobile App Plan, decision Q4.
- `client-core`, `shared`, `tokens` and `i18n` use no DOM or browser API. Source: lint rule `toki/client-core-globals`; `CLAUDE.md`, boundary rule 2.
- Not in this ticket: lint rules for mobile (MOB-04), the local server connection (MOB-05), CI for mobile (MOB-06), the test harness (MOB-07), tokens, fonts and icons (MOB-08 to MOB-10), and the native build of `platform` (MOB-11). Source: Toki Blueprint, Mobile App Plan, MM1.

## Open questions

- What are the app's display name, iOS bundle identifier and Android package name? Once an app is published in a store, these cannot change.
- Are the native `ios/` and `android/` folders committed, or generated by `expo prebuild` and ignored by git?
- Does Expo build with pnpm's default (isolated) `node_modules` layout, or does the workspace need the hoisted layout?
- Does the root `pnpm dev` also start the mobile bundler?
- How does Metro resolve the `.js` import specifiers that the workspace packages use for their `.ts` files (for example `export * from "./email.js"` in `@toki/shared`)?
