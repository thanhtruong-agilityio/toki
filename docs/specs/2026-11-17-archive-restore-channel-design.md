# Archive and restore a channel (screens) design

Date: 2026-11-17 · Status: draft for review
Intent: docs/intents/archive-restore-channel.md (Thanh Truong)
Ticket: TOKI-101

## Goal
Admins need to put a channel away and bring it back, and members need to read what was said in a channel that was put away. The server has the two requests (TOKI-029 R14) and the client has the two commands `archiveChannel` and `restoreChannel` (TOKI-032 R15); no screen uses them. This work builds: the "Archive channel" button of the Details panel with its confirmation; the page a member sees when they open an archived channel, with the name, the topic, an "Archived" label, the place of the history and, where the composer would be, the notice "This channel has been archived"; and the "Restore" button beside an archived channel in Browse channels. The messages of the history are drawn by TOKI-041, which this ticket does not wait for: until it lands the place is empty (Scope, R14, concern 9). Nothing deletes a channel (D-029, AC-052).

### The flow of an archive
```
Archive pressed
  readChannel(id) -> count          (failed: held count, else one toast, no dialog)
  ConfirmAction names #name and the count
    Cancel / Esc / outside -> nothing changed
    Confirm -> offline? explanation, dialog stays
            -> archiveChannel(id), dialog busy
                 ok   -> toast "Archived #name" (no Undo); store removes the entry, keeps the detail
                         route draws ArchivedChannelPage at the same address (R13)
                 409  -> readChannel(id), close, one toast
                 403/404 -> close, onNoAccess() -> the not-found view
                 other -> dialog stays, one toast
```
Other members see the change at their next refresh or read; live update is concern 5 (decided).

### The flow of an open
```
Browse "Open" (member) -> /c/{id}   id not in the list, never seen
  -> UnjoinedView -> UnjoinedChannel reads the channel (readChannel)
  -> the store holds the detail (archived true, isMember true), the entry stays absent
  -> the store emits: the route draws ArchivedChannelPage at once   (R13 before (b))
       onMember, if it still runs: memberChecked + one refresh(); the archived detail is kept
  -> the page reads the channel once more (readChannelOnce, R16)
```
Archived by another Admin while the channel is open (R13 (iv)): a `readChannel` that answers first gives the page; a `refresh()` that answers first drops the detail and gives #general by TOKI-033 R21 (c).
