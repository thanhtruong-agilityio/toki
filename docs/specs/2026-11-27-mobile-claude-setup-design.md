# Set up Claude for the mobile app design

Date: 2026-11-27 · Status: draft for review
Intent: docs/intents/mobile-claude-setup.md (Huy Nguyen)
Ticket: TOKI-148

## Goal
The engineers who build the phone app open Claude sessions in the repository. A session learns the project's rules from `CLAUDE.md` and from the rule file of the area it works in, but no rule file covers `apps/mobile`, so the decisions of the mobile skeleton (TOKI-146) must be repeated in every session. After this change a session that works on `apps/mobile` loads `.claude/rules/mobile.md` by itself, and `CLAUDE.md` names it with the other rule files.

## Scope
- In:
  - A new rule file `.claude/rules/mobile.md` for `apps/mobile`, written from the merged mobile-app-skeleton spec and the official documentation of Expo, React Native and Expo Router.
  - The mobile commands of TOKI-146 in that rule file.
  - The line of "Claude configuration" in `CLAUDE.md` that lists the area rule files.
- Out (not now):
  - `packages/ui-native`: the ticket that creates it adds it to `CLAUDE.md` and to the `paths` of the rule file (concern 2).
  - Mobile lint rules and boundaries: MOB-04. Mobile configuration and secrets: MOB-02. CI: MOB-06. The test harness: MOB-07.
  - A hook for the generated native folders (concern 3).
  - Any change to `.claude/settings.json`, the hooks or the permission lists.
  - The `apps/mobile` line of "Repository layout" and the three commands in "Commands" of `CLAUDE.md`: TOKI-146 adds them (its R23).

## Requirements
- R1. `.claude/rules/mobile.md` exists. Its front matter has a `paths` list with exactly one entry, `"apps/mobile/**"`.
- R2. The rule file opens with the same two lines as the other area rule files: the title `# Mobile rules`, then "Each statement is followed by its source. Rules of this project come first; rules of the tool are kept apart in "External standard"."
- R3. The rule file has two sections, `## This project` and `## External standard`, in that order. Every statement in either section is followed by a line that starts with `Source:`.
- R4. Every `Source:` line of "This project" names a file on `main`: a merged spec with its requirement or concern number, `CLAUDE.md`, `eslint.config.js`, a `package.json` or another file of the repository. Every `Source:` line of "External standard" is a link to `docs.expo.dev`, `reactnative.dev` or `expo.github.io`.
- R5. "This project" states that the app runs as a development build and never in Expo Go; source: the mobile-app-skeleton spec, R12.
- R6. "This project" states that `apps/mobile/ios` and `apps/mobile/android` are generated by `expo prebuild` and never committed, and that a native setting goes into `app.config.ts` or a config plugin; source: the same spec, R13 and concern 2.
- R7. "This project" states that an Expo package is added with `npx expo install`, pinned to one exact version, and that `npx expo install --check` reports no mismatch; source: the same spec, R3 and R4.
- R8. "This project" states the module format of the Metro configuration file as TOKI-146 built it: `apps/mobile` is an ES module, and `metro.config.js` is an ES module when the Expo SDK in use loads one, otherwise `metro.config.cjs` with its lint block; source: the same spec, R24 and the Design section, and `apps/mobile/package.json`.
- R9. "This project" states that a relative `.js` import from a file under `packages/` resolves to its `.ts` file through the Metro fallback, and that no package is changed for Metro; source: the same spec, R9 and concern 5.
- R10. "This project" states that the root `pnpm dev` does not start Metro; source: the same spec, R20 and concern 4.
- R11. "This project" states that the app id `dev.toki.mobile` is a placeholder until store publishing is set up; source: the same spec, R5 and concern 1.
- R12. "This project" lists the commands of the app, each with what it does: `pnpm --filter @toki/mobile start`, `pnpm --filter @toki/mobile ios` and `pnpm --filter @toki/mobile android`. Their source is `apps/mobile/package.json`. No other command is listed.
- R13. "External standard" states at most eight rules, each with its link, taken from the official pages on development builds, Continuous Native Generation, `npx expo install`, Expo Router file-based routes, and the React Native performance overview.
- R14. Every rule, command and path named in the rule file exists on `main` when the ticket is built: `grep` for each path and script name in the rule file finds it in the tree.
- R15. In "Claude configuration" of `CLAUDE.md`, the sentence that lists the area rule files names `mobile` as well, with what it covers: "`mobile` (the phone app)". No other line of `CLAUDE.md` changes, and nothing is removed from it.
- R16. `.claude/settings.json`, `.claude/hooks/` and `.claude/commands/` do not change.
- R17. `pnpm format:check` exits 0 after the change.
- R18. A new Claude session that opens a file under `apps/mobile` shows `.claude/rules/mobile.md` among its loaded rules, and a session that opens only a file under `apps/web` does not.

## Design
### Layout
```
.claude/rules/
└─ mobile.md     paths: apps/mobile/**; "This project" then "External standard"
CLAUDE.md        one sentence of "Claude configuration" names `mobile`
```
- The rule file follows the shape of `.claude/rules/web.md` and `packages.md`: front matter with `paths`, a title, the two-line preface, then "This project" and "External standard". Each statement is one bullet, and its `Source:` line is indented under it.
- The rule file repeats the three commands that TOKI-146 puts in "Commands" of `CLAUDE.md`. `.claude/rules/ticket.md` asks a command to live in the rule file of its area; at the time of TOKI-146 there was no mobile area, so `CLAUDE.md` holds them too, and this ticket removes nothing from `CLAUDE.md` (intent constraint).
- The rule file states rules only for code that exists. A rule for `packages/ui-native`, push, sign-in or the mobile lint boundaries is added by the ticket that builds it.

### Order of work
- This ticket is built after the code of TOKI-146 is merged, so that every path and command it names exists (R14, concern 1).

## Testing
- R1 to R13 are checked by reading the rule file against this spec.
- R4 and R14 are checked with `grep`: each `Source:` path of "This project" and each path or script name in the rule file is found in the tree on `main`; each link of "External standard" opens.
- R15 and R16 are checked with `git diff --stat main`: only `.claude/rules/mobile.md` and `CLAUDE.md` change, and the diff of `CLAUDE.md` is one sentence.
- R17 is checked with `pnpm format:check`.
- R18 is checked by hand: open a Claude session in the repository, read a file under `apps/mobile`, and see the rule file listed among the loaded rules; then do the same with a file under `apps/web`.
- No data is used.

## Data safety
- The rule file holds no secret, token, key or personal path. It names the placeholder app id only.

## Open questions from the intent
- Does this ticket wait until the `apps/mobile` skeleton (TOKI-146) is merged? Answered: yes, after the code of TOKI-146 is merged. See concern 1.
- Is `packages/ui-native` named in `CLAUDE.md` and in the rule file's `paths` now, or by the ticket that creates it? Answered: by the ticket that creates it. See concern 2.
- Does the mobile rule file come with a hook for the generated native folders? Answered: no hook. See concern 3.
- Which official standards go into "External standard"? Answered: the official docs of Expo, Expo Router and React Native, at most eight rules. See concern 4.
- Clarify gap: the intent's Problem says the "Boundary rules" section of `CLAUDE.md` describes the web app only. Does this ticket change it? Answered: no. Boundaries live in `eslint.config.js` and `tools/lint-rules/` and are changed with their lint rules by MOB-04, which updates that section.

## Areas of concern
1. The rule file and its commands describe `apps/mobile`, which exists only once the code of TOKI-146 is merged; the intent's constraints add no command for code that does not exist yet. Decided: build this ticket after the TOKI-146 code is merged, and check every named path and command against `main` (R14). Decided by Huy Nguyen (product owner) on 2026-11-27, as recommended. Owner: Huy Nguyen (product owner).
2. `packages/ui-native` is in the Blueprint layout but not in the repository. Naming it now would point a rule file at an empty path and describe a package that has no rules yet. Decided: leave it out; the ticket that creates `packages/ui-native` adds it to "Repository layout" of `CLAUDE.md` and to the `paths` of `mobile.md`. Decided by Huy Nguyen (product owner) on 2026-11-27, as recommended. Owner: Huy Nguyen (product owner).
3. A hook could refuse an edit under `apps/mobile/ios` or `apps/mobile/android`. Git already ignores both folders (TOKI-146, R13), so an edit there is never committed, and a hook would also stop a needed local look at a generated file. Decided: no hook; the rule file states the rule (R6). Decided by Huy Nguyen (product owner) on 2026-11-27, as recommended. Owner: Huy Nguyen (product owner).
4. "External standard" needs a fixed list of sources so it stays short and checkable. Decided: the official docs of Expo (development builds, Continuous Native Generation, `npx expo install`), Expo Router (file-based routes) and React Native (performance overview), at most eight rules (R13). Decided by Huy Nguyen (product owner) on 2026-11-27, as recommended. Owner: Huy Nguyen (product owner).
