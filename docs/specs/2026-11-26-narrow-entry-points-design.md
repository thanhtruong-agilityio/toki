# Entry points on narrow screens design

Date: 2026-11-26 · Status: draft for review
Intent: docs/intents/narrow-entry-points.md (Thanh Truong)
Ticket: TOKI-092

## Goal
A person on a phone needs the same reach as a person on a laptop: search, People, Preferences, Admin (for an Admin), Set status, Pause notifications, Focus time and Sign out. D-053 names search, the account menu, status, Pause and Focus time for the More sheet, and D-067 forbids a desktop-only feature; People, Preferences and Admin come from journey F38 and the plan line of this ticket, and Sign out from D-158 through the plan line of TOKI-099. Under 720 px the shell draws neither the sidebar nor the account card (TOKI-015 Table G), and it draws the More tab only when it is given a sheet (TOKI-015 R6), so today none of these has an entry point on a phone.
After this change `apps/web` gives the shell a More tab and a sheet. The sheet lists Search, the sections of the shell marked `more`, and an account section made of the entries that the account menu registry holds. A chosen row, Sign out included, closes the sheet first and then does its work, so focus is back on the More tab before the bar can be hidden (GAP-39, TOKI-099 concern 12).

  - The Sheet layer itself, its focus rules and its look (TOKI-014), and the More tab (TOKI-015). The People page and its section row (TOKI-079); the Preferences page frame (TOKI-078) and the Preferences section row, which TOKI-099 R21 added to `sections.ts`; the Admin page and its row (TOKI-025).

## Design
### The sheet, row by row
| Row | Source | Icon | On choose |
| :---- | :---- | :---- | :---- |
| Search | fixed | `search` | close, then `open({ returnFocusRef })` of the palette |
| People, Admin (Admins), Preferences | `navSections` with `more: true` | the section's | close, then `router.navigate({ to })` |
| Set status | registry `setStatus` | `smile` (TOKI-056) | close, then its `onSelect` (opens the status dialog) |
| Pause notifications: options, Resume now | registry `pause` group | `bell-off`, `bell` (TOKI-076) | close, then its `onSelect` (online gate, command, toast) |
| Focus time: options, End focus now | registry `focus` group | `bolt` (TOKI-076) | close, then its `onSelect` |
| Sign out | registry `signOut` | none (TOKI-099 concern 9) | close, then its `onSelect` (TOKI-099 R7) |

The registry's `preferences` entry has no row, because the Preferences row of the section list is the same page (concern 2).

### How the pieces meet
- `ShellBody` already holds `navSections`, the router and the signed-in user. It calls `useMoreSheet()`, gives the shell the More tab and gives `MoreSheet` the hook's result and the list. Nothing in `ui-web` changes: the shell's `moreTab` and `NavSection.more` were made for this (TOKI-015 R6, R9).
- `useMoreSheet()` returns `{ open, setOpen, tabRef, choose }`, and owns the history entry of R17. The More tab's ref is the one `moreTab.ref` carries and the one the Sheet gets as `returnFocusRef`, because Safari and Firefox on macOS do not focus a button that is pressed with a finger or a mouse (TOKI-014 R13). It also watches `useNarrow()` (R11).
- `choose` stores a function and closes; the effect that runs it is in `MoreSheet`, the parent of the Sheet, whose effects run after the Sheet's own cleanup in one commit. This is the order the palette uses for its own choices (TOKI-071 R9), so a dialog opened by a row, the status dialog or the palette, records the More tab as its opener and returns focus there.
- Rows are built in `more-rows.ts` from plain data and drawn by `MoreSheet.tsx`, so the order, the Member and Admin cases and the Preferences rule are tested without a DOM.
- The sheet sits inside `AppShell`, as a child, so a toast that a row causes (the pause started, the offline explanation, a failed sign-out) is drawn by the shell's provider over the bottom bar (TOKI-015 R23). The sheet is already closed by then, so no toast lies over its rows.

## Areas of concern
1. The order of People, Admin and Preferences. The plan line and journey F38 list "Search, People, Preferences, Admin" and state no order to check; the prototype's own More sheet (line 2155) lists people, admin, prefs, and so does its section list (line 1199), which TOKI-025 R2 and TOKI-099 R21 follow for the shell's rows. Accepted: the sheet draws the `more` rows in the order of the shell's section list (R3), which is the prototype's. Reason: the sheet then has no list of its own to keep in step with the sidebar and the rail, and a row added later by a ticket lands in one place for all three. If the owner wants Preferences before Admin, `buildMoreRows` sorts by a fixed list, one function and its table test change. Owner: Thanh Truong.
2. Preferences twice. The account menu of TOKI-099 has a Preferences entry (R4 there) and the sheet has a Preferences section row. Decided in this spec: the sheet draws the section row and skips the registry entry whose id is `preferences` (R7, R10), so the page is reached by one row, and the person never sees two rows with one word that lead to one page. To tell the entry apart the registry stamps the id on a registered item; this is a change to merged TOKI-099 code (R10), a stamped id and nothing else, and the alternative, a filter on the label, would break in Vietnamese. Owner: Thanh Truong.
3. Sign out and the closing rule. TOKI-099 concern 12 (merged) says the sheet closes when an entry is chosen (GAP-39), before the call, so that focus is back on the More tab before the shell hides the bar. Decided by TOKI-099 concern 12: Sign out closes the sheet first like every other row (R8, R9). What this leaves open, the visible wait on a phone, is concern 8. Owner: Thanh Truong.
4. A sheet that outlives the narrow layout. The Sheet layer stays open if the window grows (TOKI-014 Sheet: its owner closes it). Decided in this spec: the sheet closes at 720 px (R11), because a sheet at the foot of a laptop window has no tab that opens it and no way to tell what it is for. Focus is not given back, since the More tab is not visible. Owner: Thanh Truong.
5. Who is signed in. The phone draws no account card, so nothing on a phone shows the person's name or current status; Set status opens a dialog that shows the current text, but a person who has set one and wants to read it has no place to look. The log (D-053, F38) lists the rows of the sheet and names no identity line. Not decided. Proposal, not a decision: the account group starts with one non-pressable line with the avatar, the name and `accountDetail` of TOKI-099 R2 (the status, otherwise the role), the same data the card draws, no new text; it adds one row of 56 px and one test, and R3 gains a `person` row. Without it the sheet is as R3 says. Owner: Thanh Truong (product owner).
